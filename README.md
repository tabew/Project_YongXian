# Project YongXian

使用 **Godot 4.7** 开发的 2D 肉鸽游戏项目。目前包含主菜单、**无限世界 + 区块流式加载 + 14 种生物群系 + 主路/支线路网**、右上角小地图，以及一个可用 WASD 控制、带加速度的占位主角。已加入可配置近战武器系统、第一把长剑与可重生训练靶。

## 近战武器

鼠标瞄准，左键挥击，按住连续攻击，Q 切换长剑 / 长棍。长剑做大范围扇形横扫；长棍做 40° 小扇形挥舞，并带由远到近的大小、明暗过渡和短弧形拖尾。出生点附近的训练靶可验证伤害、暴击与击退。

- **调整现有武器**：在 Inspector 编辑 `resources/weapons/longsword.tres` 或 `resources/weapons/long_staff.tres`。
- **长剑类通用模板**：[swing_weapon_template.tres](resources/weapons/templates/swing_weapon_template.tres)，150° 扇形横扫。
- **长棍类通用模板**：[staff_weapon_template.tres](resources/weapons/templates/staff_weapon_template.tres)，40° 小扇形与由远到近过渡。
- **添加同类武器**：复制对应模板，修改唯一 ID、名称、数值和贴图，再加入玩家的 `weapon_loadout` 数组；无需新增脚本或攻击场景。
- **添加不同类型武器**：继承 `WeaponDefinition` / `WeaponAttack`，配置独立攻击场景，无需修改玩家或控制器。
- **完整说明**：[武器架构、参数、扩展和测试](docs/weapons.md)。

## 路网：主路 + 支线

路网用的是和地形**同一套思路**——噪声场，所以天然兼容无限区块，不需要另建一张全局图。

| | 主路 | 支线 |
|---|---|---|
| 来源 | 低频噪声的零等值线 | 高频噪声的零等值线 |
| 阈值 | `abs(noise) < 0.0125` | `abs(noise) < 0.0220` |
| 频率 | 0.0022 + 域扭曲 | 0.0075 |
| 贴图 | 石板路 | 土路 |

**为什么是零等值线**：`abs(noise)` 很小的地方正好落在噪声的过零点上，而二维噪声的过零点集合天然是一条条蜿蜒的连续曲线——低频给出又长又宽的主干道，高频给出又短又密的岔路。全程只用一次噪声采样，不用寻路、不用存图。

**路一定可通行**：路跨过水面时自动换成木桥贴图，压在山地上就是山道。这样主干道永远顺得下去，不会被一片海或一道山脊截断——对肉鸽的推进节奏来说这点很关键。

**生物群系完全没动**：路只是**渲染层替换**——`ChunkData.terrain` / `biome` 一个字节都没改，只是路所在格子的贴图换成路面。所以既保住了原有群系，也不用为「16 种地形 × 3 种路」准备 48 张图。

实测覆盖率（768×768 格范围，三个种子）：

| | 占比 |
|---|---|
| 主路（石板） | 1.4% ~ 1.9% |
| 支线（土路） | 2.5% ~ 2.9% |
| 木桥 | 1.2% ~ 1.6% |
| **路网合计** | **5.5% ~ 6.2%** |

## 小地图

右上角，覆盖范围正好等于区块加载范围（默认 5×5 区块 = 160×160 格）。

| 设计 | 说明 |
|------|------|
| 数据来源 | **直接读已加载区块的字节数据**，一行噪声都不重算 |
| 右上角小地图 | 保持显示玩家附近已加载的 5×5 区块，不使用探索迷雾 |
| 全屏地图 | 按 M 铺满窗口，至少显示以玩家为中心的 15×7 区块，并包含更远的已探索区域 |
| 探索记录 | 保存所有已加载观察过的区块快照，区块离开缓存后仍可显示，生成新世界时清空 |
| 分辨率 | 小地图 2 格 1 像素；全屏地图 1 格 1 像素，显示更多地形细节 |
| 配色 | 调色板从图集上现取，避免颜色表和图集两边各写一份而对不上 |
| 路线高亮 | 路面在地图上偏向暖黄，不管在什么群系上都一眼能看出路线 |
| 跳过无意义重建 | 区块或探索进度没变就不重画，站着不动时零重建 |
| 网格 | 每 16 像素一条线 = 一个区块，方便对位 |

原版小地图底图重建实测为 **1.16 ms/次**；现在仍只在区块数据变化时重建。

## 无限世界与区块加载

世界没有边界：地形与路网只由 `(世界种子, 格子坐标)` 决定，**与区块划分无关**，所以任意区块都能独立生成，区块之间不会出现接缝，也不需要读取邻居数据。

| 概念 | 取值 |
|------|------|
| 格子 | 16 × 16 像素 |
| 区块 | 32 × 32 格 = 512 × 512 像素 |
| 加载半径 | 2 个区块 → 常驻 25 个区块 |
| 卸载半径 | 3 个区块（比加载半径大，留迟滞避免边界抖动） |
| 数据缓存 | 512 个区块（每块 3 KB，约 1.5 MB） |

区块的加载 / 卸载由 [chunk_manager.gd](scenes/world/chunk_manager.gd) 负责，只在玩家跨过区块边界时才重算要显示的范围。

### 性能设计

| 手段 | 说明 |
|------|------|
| 生成放工作线程 | 噪声采样是主要开销，丢给 `WorkerThreadPool`，主线程只负责铺格子 |
| 每线程一个生成器 | 每个工作线程各持一套 `FastNoiseLite`，避免多线程共用同一实例 |
| 每帧预算 | 提交生成、铺格子、回收区块各有上限，不会一口气卡住 |
| LRU 缓存 | 走回头路直接命中缓存，一次噪声都不重算 |
| 区块节点池化 | `TileMapLayer` 复用，卸载区块不销毁节点 |
| 格子坐标局部化 | 图层的节点位置承担世界偏移，格子坐标只用 `0..31`，四叉树不随玩家走远而膨胀 |
| 复用时不 `clear()` | 铺图总是写满 32 × 32 格，所以复用的图层不需要先清空 |
| 小地图走数据不走噪声 | 见上一节 |

### 实测数据（Godot 4.7，32 核）

```
区块数据生成    1.7 ~ 1.9 ms/块   ← 工作线程，不占主线程
铺进 TileMap    0.67 ms/块        ← 主线程

瞬时跨越 25 个区块（相当于瞬移）时，主线程开销：
  ChunkManager             平均 0.120 ms/帧   最差 2.99 ms   超 4ms 的帧 0/150
  ChunkManager + 小地图     平均 0.184 ms/帧   最差 2.77 ms   超 4ms 的帧 0/150

小地图底图重建            1.16 ms/次，且数据没变就跳过

正确性：
  sample_terrain 与已铺格子逐格比对     0 / 3072 不一致
  区块路网与即时查询比对                0 / 1024 不一致
  小地图底图与世界数据逐像素比对        0 / 256 不一致
  相邻区块交界两侧                      0 处接缝
  is_walkable 判定                      0 处不一致
  木桥出现在陆地上                      0 处
  同种子不同生成器实例                  完全一致
  回到原点                              25 个区块全部命中缓存，0 次重新生成
```

帧预算（16.7 ms）占用约 1%，掉帧帧数为 0。

## 生物群系

群系由 **海拔 + 温度 + 湿度** 三套噪声共同决定：海拔先分出海洋 / 海岸 / 平原 / 山地 / 雪峰，平原再按温湿度细分。

| 群系 | 主要地形 | 群系 | 主要地形 |
|------|----------|------|----------|
| 深海 | 深水 | 沼泽 | 沼泽 |
| 海洋 | 浅水 / 浮冰 | 针叶林 | 针叶林 |
| 海岸 | 沙滩 | 苔原 | 苔原 |
| 沙漠 | 沙漠 | 雪原 | 雪原 |
| 稀树草原 | 稀树草原 | 山地 | 石地 / 山地 |
| 草原 | 草地 | 雪峰 | 雪峰 |
| 森林 | 森林 | 热带雨林 | 雨林 |

每个群系还配了「次要 / 点缀」两种地形，由一张高频 `variation` 噪声决定用哪一种，所以群系内部也有过渡，不会是一整块纯色。

**为什么需要对比度拉伸**：单纯形噪声的值几乎都挤在 0.5 附近，直接拿去判定的话，沙漠、雨林、雪峰这些需要极端温湿度的群系永远出不来。所以温湿度和海拔都过了一道 `_sharpen()` 把值往两端拉。

768 × 768 格范围内的实测分布：

| 群系 | 占比 | 群系 | 占比 |
|------|------|------|------|
| 海洋 + 深海 | 23.6% | 苔原 | 5.7% |
| 雪原 | 16.2% | 针叶林 | 5.2% |
| 森林 | 11.2% | 沼泽 | 5.0% |
| 草原 | 8.6% | 稀树草原 | 3.5% |
| 山地 | 7.4% | 沙漠 | 1.8% |
| 海岸 | 6.0% | 雪峰 | 0.3% |
| 热带雨林 | 5.7% | | |

## 主角移动

[scripts/player.gd](scripts/player.gd) 用 `move_toward` 做速度插值：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `max_speed` | 220 | 最大速度（像素/秒） |
| `acceleration` | 1400 | 按住方向键时每秒增加的速度 |
| `friction` | 1800 | 松开按键后每秒衰减的速度 |
| `collide_with_terrain` | true | 是否阻挡深水 / 浅水 / 山地 / 雪峰 |

按住方向键约 **0.16 秒**到达最大速度（每帧 +23.3），松开约 **0.12 秒**停下（每帧 −30）。位移按 X/Y 分轴推进，贴着海岸走不会卡住。

碰撞不查区块，而是直接问 `WorldGenerator` 这一格能不能站——生成函数是纯的，所以判定结果和画面永远一致，也不用等区块加载完。查询结果按格子缓存，一帧最多算两次。

## 热带雨林怪物“给”

“给”只会随已加载区块生成在热带雨林的可通行格子中，同一种子与区块会得到稳定一致的随机位置。玩家进入 10 格范围后，怪物只有在视线无阻挡时才产生攻击意图：距离 6 至 10 格（包含两端）时拾取 1 格内的石子投掷，低于 6 格时弹跳到玩家面前并近战。手边没有石子时停止本次远程攻击，不会改用跳跃。两种攻击均造成 1 点伤害且攻击间隔均为 1 秒。“给”拥有 100 点生命，玩家每个新世界以 10 点生命开始。

所有怪物应继承 `scripts/monsters/base_monster.gd`。该模板使用场景中的 `TargetRayCast`（`RayCast2D`）检测 `StaticBody2D` 等物理墙体，同时逐格检查程序化地形的可通行性；视线受阻时通过 `AStarGrid2D` 绕行，不能隔墙锁定、投掷或跳跃穿墙。基类不定义索敌范围，各怪物自行定义感知与追踪距离。“给”只限制刷新位置必须是热带雨林，生成后可以追逐玩家进入其他群系。

统一道具基础层来自 `inventory` 分支：`scripts/items/item_data.gd`、`scripts/items/ingredients/ingredient_data.gd`、`ingredients_model.gd` 以及炼金/物理属性基类保持原路径和原 UID，供背包、合成和世界物品共同使用。

当前地图尚无正式石子，上传版本不生成临时石子，因此“给”在远程范围内找不到石子时会停止本次攻击。地图团队接入正式石子时，应继续使用同一套 `IngredientData` / `IngredientModel`，加入 `throwable_stones` 组并实现 `throw_at(target, damage)` 方法；怪物代码不依赖具体石子类型。

回归测试：

```

godot --headless --path . res://tests/test_rainforest_spawner.tscn
```

## 已知限制

- **浮点精度**：主角世界坐标走到约百万像素之外后，位置精度会明显下降。真正的超远距离探索需要引入浮动原点（把已加载区块整体平移回原点附近）。
- **地形碰撞用代码判定**，没有走 TileSet 物理层；两者视觉上等价，但物理层能直接配合 `move_and_slide`。
- **路网还没有节点**：目前只有"路"，路上还没有战斗 / 事件 / 宝箱 / Boss 这类肉鸽节点。
