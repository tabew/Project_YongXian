# Project YongXian

使用 **Godot 4.7** 开发的 2D 肉鸽游戏项目。目前包含主菜单、**8 层关卡图 + 15 个随机陆地箱庭区域 + 区块流式加载 + 14 种生物群系**、右上角小地图与 M 全屏探索地图、一个可用 WASD 控制带加速度的占位主角，以及**只长在自然地面上、比角色高、可用武器清除的星露谷式草丛**。已加入可配置近战武器系统、第一把长剑与可重生训练靶，以及**击杀 / 炼金双来源的局内升级系统**。

## 运行调试

- **F1 物资**：搜索并获取任意已注册物品，可按材料、武器、药水筛选；数量可调，“全部材料”一次补齐所有材料。物品直接进入背包，药水各自生成独立实例。
- **F2 增益**：搜索全部局内升级，直接设置层数、移除单项或清空增益。无须升级或装备对应武器，不消耗经验与正常待选次数；武器卡在装备对应武器后生效。
- 再按当前功能键或 **Esc** 关闭，F1 / F2 可直接切换面板。窗口打开时暂停战斗，关闭时恢复先前暂停状态，正常升级选项会在调试改造后刷新。
- 层数遵守各卡上限；同组终极改造直接替换。修改仅影响本局，开新局清空增益。

验证：`godot --headless --path . --script res://tests/test_cheat_panel.gd`；加图形参数 `--rendering-method gl_compatibility` 并使用 `-- --capture` 可保存桌面与紧凑窗口截图。


## 近战武器

鼠标瞄准，左键挥击，按住连续攻击。武器从物品栏选中即装备（默认第 1 格长剑、第 2 格长枪，开局选中长剑），左键攻击。Q 循环切换、`starting_weapon` 自动装备、`player.equip_next_weapon()` 三个入口都已移除，玩家侧没有绕过物品栏的装备路径。长剑做大范围扇形横扫；长枪锁定出手时光标方向直线刺出，最远 72 像素、判定宽 6 像素，收枪不造成伤害；溜溜球参考泰拉瑞亚，球停在指针处持续命中，指针超出绳长时贴在边界上，松手立刻收回。出生点附近的训练靶可验证伤害、暴击与击退。

- **调整现有武器**：在 Inspector 编辑 `resources/weapons/longsword.tres`、`resources/weapons/spear.tres` 或 `resources/weapons/yoyo.tres`。
- **长剑类通用模板**：[swing_weapon_template.tres](resources/weapons/templates/swing_weapon_template.tres)，150° 扇形横扫。
- **长枪类通用模板**：[spear_weapon_template.tres](resources/weapons/templates/spear_weapon_template.tres)，沿光标方向直线伸刺与收枪。
- **溜溜球类通用模板**：[yoyo_weapon_template.tres](resources/weapons/templates/yoyo_weapon_template.tres)，球跟随指针并受绳长限制，松手收回。
- **添加同类武器**：复制对应模板，修改唯一 ID、名称、数值和贴图；再建一个 `resources/items/weapons/*.tres`（脚本用 `WeaponData`，`weapon` 指向它），玩家就能从物品栏装备（见 [武器只能从物品栏装备](docs/weapons.md#武器只能从物品栏装备)）。无需新增脚本或攻击场景。
- **添加不同类型武器**：继承 `WeaponDefinition` / `WeaponAttack`，配置独立攻击场景，无需修改玩家或控制器。
- **完整说明**：[武器架构、参数、扩展和测试](docs/weapons.md)。

## 局内成长（Roguelike 升级）

一局游戏内独立的成长线：**击杀怪物**（主要）与**炼金装瓶**都给经验，攒满经验就升级，每升一级弹出一次**三选一**加成卡，所有加成**只在本局生效**，开新局时全部清零。经验球生成后先停顿 0.45 秒，再直接朝玩家飞入。

- **等级曲线**：`8 + 4 × (等级 - 1)`，一局大约 11–12 级；经验超出时连续结算多级，面板会一张接一张地弹。
- **等级自带成长**：每升一级，最大生命值 / 武器伤害 / 药水效果各 +10%。**加算不叠乘**（1 级 100 生命 → 2 级 110 → 3 级 120），和升级卡直接相加；升级那一刻就把新增生命上限补到身上。
- **药水强度覆盖**：爆炸/落雷/火焰/冰冻的伤害、buff 的每跳伤害与属性修改幅度、荆棘反伤、治疗量都跟着涨；时长、半径、药水对自己的自伤有意不变（明细见文档）。
- **三选一**：每次抽 3 张不重复的卡，稀有度权重 60 / 30 / 10，连续 2 次没出稀有后下一次必出稀有。**没有重抽**，选定即消耗。
- **武器卡只出当前装备的武器**，拿过别的武器的改造不会串味。
- **代价卡**（孤注 / 薄刃 / 苦行）需要当前生命 ≥ 70% 才会出现。
- **加成卡共 34 张**：普通 9 张、精良 5 张（炼金向）、稀有 20 张（武器 10 + 机制 7 + 代价 3）。
- **生命刻度已统一**：玩家 100 点生命上限，怪物伤害同步 ×10，所以百分比与固定值加成都有可感知的分量。
- **加成一定生效**：武器卡按 id 隔离（不会串味）、长枪的长驱、重刺、连刺和钉足会作用于实际攻击、迅捷对写死时间的卡同样有效、经验球不跨区域堆积。
- **完整说明**：[等级曲线、加成生效链路、34 张卡总表、扩展方式](docs/run_progression.md)。

## 随机陆地箱庭与内部道路

[RunGraph](resources/world/run_graph.gd) 将一局组织为 **8 层、15 个区域**：原有 14 张主干和岔路地图全部保留，第 3 列额外增加一个可返回的支线箱庭。地图从左到右前 3 列依次为 **1、2、3 张地图**，同列上下接壤、相邻列左右贴合，形成横向展开的金字塔。主路径、房间类型、怪物内容、双向出入口仍由原关卡图管理。

关卡骨架现在带**房间类型与节奏**：`RoomGraph` 在既有拓扑上标注起点 / 战斗 / 奖励 / 商店 / 休息 / 事件 / Boss，主路径按节奏模板分配，关键房间由配置强制校正；生成后再过一遍硬约束校验与软约束评分，不合格就在同一主种子下换布局变体重试。全部随机走统一的 `MapRng` 种子系统，同种子必然同图。架构、配置与调试命令见 [地图生成架构](docs/map_generation.md)。

[MapSpec](resources/world/map_spec.gd) 按种子分别随机箱庭宽高，通常各为 **112–224 格**。非初始区域使用宽阔原野、狭长山谷、林间空地、折返山径、阶梯台地和双庭丘陵六类轮廓，由随机重叠庭室组成主庭与可探索侧庭。地图以陆地为主，外围由主题对应的山林围合；水面来自**世界级河流**与箱庭内的池塘。

**道路：主干 + 环路。** 每张箱庭先从西门蜿蜒穿过主庭到东门铺一条**主干**（中间两处折点，不再是直线），其余门接在主干两端形成岔口；侧庭从主干的最近点引出支路，侧庭之间再互相连通成可返回的环路——不再从主庭中心向四周放射。超过 26 格的长路段才加正弦摆动，短路段保持顺直，避免曲线过陡把路面判定甩出路面；道路跨河自动生成木桥。

**河流：跨箱庭的世界级水系。** 河流按世界坐标生成，沿一个**斜向主轴**（与世界成 26°–62°）从一侧流入、贯穿若干区域后从另一侧流出，河面宽 **6–9 格**，穿过箱庭之间的山林屏障时形成**水峡**（仍是阻挡，不会把区域打通）。同一世界里所有河流共用同一个方向、彼此平行且互不交叉（最小垂直间距 34 格），避免围出封闭水域；河流离所有出入口、落点至少 12 格，起始小屋所在区域整体不落河；区内沿岸每隔约 28 格留一小段**可涉水浅滩**，保证河不会把箱庭切成两半。池塘仍在箱庭内独立生成，与河流分开。

**区域 0 是森林主题的「起始小屋」**，每局按种子生成 **20–24 × 16–18 格**的小屋与家具，玩家出生在房内中心。石地表示可走地板；木墙与家具使用不可通行地形，由 `CottageView` 绘制小屋外观。门位于右墙，门外右侧 3 格是屋前落点；室内仅保留出生点穿门到屋前的直线道路，其他出口与侧庭道路从屋前连接，避免道路穿透墙壁和家具。初始区域不生成水域，敌人内容预算为 0；离开后小屋隐藏，返回时重新显示。

**道路只存在于箱庭内部**，连接主庭、侧庭及出入口；主路用石板、支线用土路，跨水处显示木桥。路面与空地可通行，森林、针叶林、雨林会阻挡移动，小屋木墙与家具也保持阻挡。世界总览中各箱庭外框接触，地面仍按区域归属铺设；角色依旧只从已有出入口进入下一箱庭，不能从任意接缝穿越。地形以世界坐标的低频柏林噪声生成大块连续地貌，接壤处混合相邻区域的边缘色。

草地、土路、岩土、树林和水岸的接触边沿使用像素融合与圆角过渡，跨区块保持一致；箱庭出入口附近也会逐渐混入相邻区域的地面色调，同时保留每个箱庭的单一群系与通行规则。

地面按种子随机散落**符合当前群系的材料**，每图约 20–70 个，分布疏松；小屋外优先放置两种材料。靠近后按 **E** 拾取，材料进入背包并可堆叠，已拾取点位在返回地图后不会补刷。

每个箱庭另有 **5–11 处**地表结构（按面积约每 4200 格一处，中等地图通常 6–7 处；营地、残垣遗迹、炼金台、废弃补给点、药草园）和 2–4 个**宝箱**（奖励区再加 2 个，25% 概率为珍稀箱），以及 10–24 堆散落物资。结构的实心格参与地形碰撞，落点避开道路、水域、小屋、出生点和出入口，彼此之间留出至少 8 格间隔避免挤成一堆。**木桶**只摆在营地、补给点与炼金台旁（每处 1–2 个），占一格、挡路；用武器一刀或任何范围伤害打碎后掉 1–3 根木棍，打碎状态随箱庭保存，回图不会长回来。**每张区域至少一台炼金台**，且第一台优先贴着主路放置，沿路走一段就能碰到；炼金台自带砖石地块，台面占中间三格。靠近炼金台按 **E** 打开炼金界面（再按 E / Esc / Tab 关闭），界面里把材料拖进投料框、点「开始反应」、反应完点「装瓶」。靠近宝箱按 **E** 开箱，草药、木棍、石头、炸弹会掉在附近，再按 **E** 拾取；普通箱 3 堆、珍稀箱 4 堆。除材料外还会按概率再开出一件**武器**（溜溜球 / 雷鸣 / 蜂巢，跳过开局自带的长剑与长枪；普通箱 12%、珍稀箱 35%）或一瓶**随机配方药水**（随机 2–3 种材料的炼金属性合成，最多 3 条属性，有独立 id 与「无名药水（火·迅捷）」这类名字；普通箱 25%、珍稀箱 50%），都落在箱子旁第一个可站走的格子上。同一口箱子用坐标做种子，重开世界前结果稳定。

### 材料（38 种）

材料数据在 `resources/items/ingredients/*.tres`（ID 0–37，与 `materials_table.xlsx` 一致）。地面采集按**群系**分布，每个群系 2–3 种，靠近按 **E** 拾取：

| 群系 | 材料 |
|---|---|
| 海岸 | 贝壳、浮木 |
| 沙漠 | 仙人掌刺、**沙晶**(罕见) |
| 稀树草原 | 干草束、硬壳果 |
| 草原 | 胡萝卜、野花、麦穗 |
| 森林 | 蘑菇、**枯木**(罕见) |
| 热带雨林 | 藤蔓、**巨型蕨叶**(罕见)、酸果 |
| 沼泽 | 泥炭、腐蚀苔、**透明花**(稀有) |
| 针叶林 | 松脂、**桦树皮**(罕见) |
| 苔原 | 苔藓、冻浆果 |
| 雪原 | **冰晶**(罕见)、雪苔 |
| 山地 | **铁矿**(罕见)、岩盐、**雷石**(罕见) |
| 雪峰 | **雪莲**(稀有)、冰川碎片 |

**稀有度**分普通 / 罕见 / 稀有（`IngredientData.rarity` = 0/1/2）。地面点位按 **6 / 2 / 1** 加权（`GroundMaterials.RARITY_WEIGHT`），越稀有越少见；同一份稀有度常量表也在 `GroundMaterials.RARITY` 里，供纯数据测试使用。

**怪物掉落**每种怪物一张 `MonsterLootTable`，死亡必掉一件、按权重抽：

| 怪物 | 掉落（权重） |
|---|---|
| 给 | 给毛 70 / 猴皮 30 |
| 鳄鱼 | 鳄鱼眼睛 10 / 饿甲壳 60 / 锋利牙齿 30 |
| 啥杯 | 兔皮 30 / 啥杯肉 50 / 胡萝卜 20 |
| 史 | 凝液 80 / 粘性球 20 |

炸弹不在地面生成，只从宝箱获得（`WorldPopulation._loot_pool` 会把炸弹加进每个群系的宝箱池）。开箱与拾取状态在当前会话内随箱庭保存，重开世界重置。

按 **B** 打开炼金界面，从背包拖入材料：石头提供矿物属性，木棍提供木质属性，两者反应生成固结属性；固结现在会给出「固化」效果（一段时间内减伤），矿物加火还能炼出「护己」（自己扔的药水不伤自己）。每种材料都登记了炼金属性，属性之间可以互相反应强化（同级同名两份合成更高一级，最高 3 级），属性本身是独立规则，炼金材料只是它的施加器之一。背包与快捷栏之间除了拖拽，还支持 **shift+左键** 整堆挪动：背包→快捷栏优先叠进已有的同种格子，没有同种就放第一个空格，快捷栏占满时整堆留在背包里；快捷栏→背包整格挪回。

触及出入口时先淡入**黑屏**，在全黑状态加载目标箱庭，再淡出显示新地貌。汇流区域保留来自不同主干 / 岔路的多个入口，各入口对应自己的返回方向；原有玩家生命、背包、装备与地图实体继续保存。相机仍以当前箱庭矩形设置硬 `limit`，切图时重置平滑，防止画面滑过未探索区域。

## 小地图与全屏探索地图

右上角 compact 小地图覆盖玩家周围 **512×512 格**，生成 **128×128 像素**底图（4 格 / 像素）。它使用独立生成器采样，也能显示未加载区域，并缓存采样像素；显示多个箱庭标签、当前区域标记与相机视野框。

| 设计 | 说明 |
|------|------|
| compact 数据来源 | **只画已探索区块**：与全屏地图共用同一份探索快照，没去过的地方留迷雾，不提前泄露地形 |
| 全屏地图 | 按 M 展开后显示整局横向金字塔的所有箱庭，未探索地形继续遮蔽，已探索区保留逐格内容。区域底色用多层内缩矩形**羽化**，区域之间是渐变过渡而不是硬边色块，也不再画硬边框线 |
| 缩放与拖动 | 全屏地图支持**滚轮缩放**（以光标为锚点，0.6–8 倍）与**中键拖动**平移，拖动被夹在地图范围内；每次打开回到整局适配。展开时地图在 `_input` 阶段先接管滚轮与中键，物品栏会让出滚轮，避免滚轮去切快捷栏 |
| 探索记录 | 保存当前可见箱庭已加载观察过的区块快照，区块离开缓存后仍可显示，生成新世界时清空 |
| 隐藏邻图 | 预加载的直连邻图不计入探索，也不会出现在小地图上 |
| 共享边界 | 同一区块跨越多个箱庭时，仅按当前地图矩形裁剪并记录像素，其他箱庭访问后再补入 |
| 分辨率 | compact 为 4 格 / 像素；全屏快照为 1 格 / 像素，保留详细地形 |
| 配色 | 调色板从图集上现取，避免颜色表和图集两边各写一份而对不上 |
| 路线高亮 | 路面在地图上偏向暖黄，不管在什么群系上都一眼能看出路线 |
| 更新 | 探索快照按**每帧预算**补齐（进图不再一次性拷贝整张地图，转场期间预算更高）；compact 在探索记录或采样窗口变化时重建，全屏按探索进度更新；角色、标签与相机框持续更新 |
| 箱庭标签 | compact 只标出已经探索过的箱庭楼层；全屏地图保留整局骨架 |

## 箱庭区块加载

地形与内部道路由世界种子、地图布局和格子坐标共同决定，区块可独立生成。**加载范围只覆盖屏幕会画到的部分**：当前箱庭按相机可见窗口加 3 个区块的外圈排队，直连邻图只预铺门口附近一小块，切图时再在过场里预热到达点周围的窗口。就绪判定同样只看可见窗口，走过多张箱庭也不会把整图区块和草丛堆在内存里。

| 概念 | 取值 / 行为 |
|------|-------------|
| 格子 | 16 × 16 像素 |
| 区块 | 32 × 32 格 = 512 × 512 像素 |
| 可见地图 | 每张地图独立 root，仅当前地图 visible；铺格子按地图矩形进行 cell clip |
| 邻图预铺 | 所有直连邻图在隐藏 root 中后台预加载，包括可返回的入口邻图 |
| 首次进入 | 同步补齐当前相机视口，其余整图区块后台生成与铺图 |
| 每帧预算 | 默认最多提交 4 块生成、应用 4 块图层 |
| 数据缓存 | LRU 缓存上限 512 个区块，同种子跨地图复用 |
| 换种子安全 | 等待旧任务结束并推进 epoch，清空旧缓存，防止旧种子结果混入新世界 |

区块管理由 [chunk_manager.gd](scenes/world/chunk_manager.gd) 负责。后台生成使用 `WorkerThreadPool` 与独立生成器，主线程按预算铺图；`TileMapLayer` 池化复用，格子坐标保持在区块本地范围。共享边界区块的数据可以复用，但各地图图层分别裁剪，隐藏邻图不会出现在当前主视图。

## 地图草丛

星露谷式牧草：[WorldGrass](resources/world/world_grass.gd) 是纯函数数据层，[GrassView](scenes/world/grass_view.gd) 按 **8x8 格一块**绘制，随区块铺图生成。

| 规则 | 说明 |
|------|------|
| 一簇一丛 | 每簇 5-8 片叶子从同一个根心长出、叶尖向外散开，根部带阴影，看起来是"一丛草"而不是几根草 |
| 比人高 | 一簇 20-29 像素，比 16 像素的角色更高，才盖得住人 |
| 与角色的前后关系 | 按**人物脚底**逐簇排序：草根在脚底以上就画在人物背后（人踩在草上），在脚底以下就画在人物前面（草盖住腿）。只有**和角色重叠的那一块**才拆成前后两层（其余整块归层，只改 `z_index`），并且只在真的跨过某簇草根时才重绘，所以走路时不会每帧重画 |
| 生长面 | 各群系的自然地面：草地最密，沼泽 / 稀树草原 / 苔原 / 雪原 / 石地 / 沙地依次变稀；水面与阻挡地形不长。每张箱庭都长得出草 |
| 配色跟随地面 | 草地是绿草，雪原是顶雪草，沙漠与沙滩是枯草，稀树草原是干黄草，沼泽是芦草，石地是石缝草 |
| 自然成片 | 簇心在格内自由取点（不对齐格子），另有一层平滑的大块密度噪声：同一片地方要么茂密要么稀疏，中间自然过渡 |
| 确定性 | 同种子同坐标必然同一簇；换种子换布局，R 重建世界重置 |
| 排除区 | 小屋与门廊、五类结构占地、宝箱 / 掉落 3x3、地面材料点、出入口 3 格内都不长草 |
| 隐藏邻图 | 只绘制当前可见地图的草丛；隐藏预加载的邻图不绘制也不长 |
| 清除 | 长剑 / 长枪 / 溜溜球的挥击形状划过即清除（[weapon_attack.gd](scripts/weapons/weapon_attack.gd) 的 `_clear_grass`），溅少量草屑并播放 `cut_grass` 音效 |
| 持久化 | 清除状态按箱庭本局保留，离开再返回不补刷；只有重建世界才重新长满 |
| 性能 | 按 8x8 格（128 像素）切块，块越小除草时的重绘越便宜；草块在全局格索引里注册，挥砍只按形状包围盒查邻近 1-4 块，不扫描全图草簇 |
| 懒生成 | 只生成玩家周围 1 个区块半径内的草（视野在 2 倍缩放下约 1.3x0.7 个区块），每帧最多补 8 块、黑屏转场期间 24 块；走一步补一片，**进入地图时不再同步算完整张图** |

层级：草层容器 `z_index = 0` 并排在角色之前，每个草块按人物脚底决定自己是 0（角色背后）还是 1（角色前面）；武器挥击与怪物血条为 2，永远在最上。怪物暂时仍画在所有草之下。

草丛不参与碰撞，也不影响通行与寻路；数据来自区块的 terrain / route 字节数组，与铺出来的地形永远一致，不额外采样噪声。音效素材由 [tools/generate_sfx.py](tools/generate_sfx.py) 程序化生成（`cut_grass`），换正式素材时覆盖同名文件即可。

切图开销：箱庭入口的实体、地面材料与草丛都按需生成，并且**在过场动画里就开始准备下一张图**——黑屏一开始就排好材料点位与到达点周围的草丛，动画期间逐帧生成（每帧 24 块，平时 8 块），小地图快照同样在转场期间加大预算。一局里实测相邻箱庭进图约 25 ms，转场全程最差帧约 17 ms（60 fps 以内）。

## 生物群系

保留 14 种群系与 16 种地形数据定义。**每张区域严格只有一个 `MapSpec.biome_id`**：其完整矩形内的所有格子，包括围合边缘、室内和池塘，`sample_biome()` 都返回这一群系。区域主题按世界种子打乱分配，初图固定为森林。正式游戏从现有怪物定义自动取可用群系，所有战斗与 Boss 区域都选择怪物池支持的主题；目前为稀树草原、草原、森林或热带雨林，并保留至少一个雨林战斗区域。其他房型保留多样主题，新增怪物配置后自动扩展战斗群系。下表说明数据定义中的主要地形对应关系；实际区域按主题配置可走地面、阻挡地形和边界。

| 群系 | 主要地形 | 群系 | 主要地形 |
|------|----------|------|----------|
| 深海 | 深水 | 沼泽 | 沼泽 |
| 海洋 | 浅水 / 浮冰 | 针叶林 | 针叶林 |
| 海岸 | 沙滩 | 苔原 | 苔原 |
| 沙漠 | 沙漠 | 雪原 | 雪原 |
| 稀树草原 | 稀树草原 | 山地 | 石地 / 山地 |
| 草原 | 草地 | 雪峰 | 雪峰 |
| 森林 | 森林 | 热带雨林 | 雨林 |

同一群系内部使用低空间频率噪声生成大簇同主题地面、连续森林与岩壁，减少高频点缀和单格碎片。地形的变化影响通行与外观，群系身份始终保持区域的固定值；池塘可以使用水地形，但不会把所在格子的群系改成海洋。

## 主角移动

[scripts/player.gd](scripts/player.gd) 用 `move_toward` 做速度插值：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `max_speed` | 220 | 最大速度（像素/秒） |
| `acceleration` | 1400 | 按住方向键时每秒增加的速度 |
| `friction` | 1800 | 松开按键后每秒衰减的速度 |
| `collide_with_terrain` | true | 是否阻挡深水 / 浅水 / 森林 / 针叶林 / 雨林 / 山地 / 雪峰（道路格除外） |
| `base_max_health` | 100 | 新世界初始最大生命；切换箱庭保留当前生命 |
| `weapon_loadout` | 已移除 | 玩家不再自带或循环切换武器，装备只能从物品栏选中使用 |

按住方向键约 **0.16 秒**到达最大速度（每帧 +23.3），松开约 **0.12 秒**停下（每帧 −30）。位移按 X/Y 分轴推进，贴着海岸走不会卡住。

碰撞不查区块，而是直接问 `WorldGenerator` 这一格能不能站——生成函数是纯的，所以判定结果和画面永远一致，也不用等区块加载完。查询结果按格子缓存，一帧最多算两次。角色同时受当前箱庭矩形约束，道路和空地可走，不能越过山林边界或从任意相接边界步行进入相邻箱庭；需经出入口黑屏转场。

切换箱庭不会回满血；只有重建新世界才恢复生命。训练靶保留在起始箱庭，离开后隐藏并暂停，返回时恢复，继续沿用原来的伤害、击退与重生行为。

完整怪物架构、生成配置与扩展说明见 [docs/monsters.md](docs/monsters.md)。

正式可刷怪箱庭保留原有的入口遭遇和按区块散布的怪物，并在废弃补给点额外安排守卫：每处按种子稳定分配 2–3 只符合当地群系及栖地的怪物，出生格位于补给点中心 8 格内。守卫平时围绕补给点 8 格巡逻；追击可越界，但与玩家拉开超过 8 格就停止攻击并寻路返回补给点。起点和事件房不刷普通怪；从第二层起其余房型（含终点 Boss 房）按预算刷怪；独立流式刷怪接口保持原行为。守卫沿用普通怪物的生命、伤害与每次入房难度倍率。HUD 显示房间类型，F3 面板显示本区域怪物数；本局击杀按怪物类型与原始生成格记录，返回旧箱庭不会复活或补刷，新开世界才清空。死亡掉落离图隐藏暂停、返图恢复。

主路径终点固定生成 Boss“贝&%*#彩？？？”，并允许符合当地群系的普通怪、入口遭遇及补给点守卫共存。Boss 共三阶段，每阶段 3000 生命；两次切段均回满血并有 4 秒免疫伤害，第三阶段结束才真正死亡。每轮普通攻击结束后等待 5 秒：第一阶段为追踪灵魂导弹与可打断的 300 血套索，第二阶段为红圈预警的随机五重下砸与触手投掷，第三阶段为 20 眼结界和可被攻击削减的蓄力怒气。独立闪避键、精英怪与召唤材料机制仍未实现，详见 [怪物说明](docs/monsters.md)。

### 怪物“仙缔”

正式箱庭中的“仙缔”既可能驻守沙漠、稀树草原、草原、森林、热带雨林区域的废弃补给点，也继续参与原有的入口遭遇和区块散布；独立流式场景仍按已加载区块和栖地刷新。玩家进入 10 格范围后，怪物只有在视线无阻挡时才产生攻击意图：距离 6 至 10 格（包含两端）时拾取 1 格内的石子投掷，低于 6 格时弹跳到玩家面前并近战。手边没有石子时停止本次远程攻击，不会改用跳跃。两种攻击均造成 1 点伤害且攻击间隔均为 1 秒。“仙缔”拥有 100 点生命，玩家每个新世界以 100 点生命开始。

击杀“仙缔”必定在死亡位置掉落一件专属材料：70% 为仙缔毛（ID 1），30% 为猴皮（ID 0），一次抽样二选一，不会空掉落或同时掉两件；普通伤害死亡和 K 击杀走同一流程，切图卸载不掉落。靠近后按 E 拾取进入现有背包。未拾取的掉落物按箱庭保存，返回时恢复；拾取后和怪物死亡记录一样不会补刷。两件材料不会加入自然散落材料生成池。

所有怪物应继承 `scripts/monsters/base_monster.gd`，AI 本体在 `scripts/monsters/ai/`：`EnemyBrain` 是通用四状态机（`Patrol` / `Chase` / `Attack` / `Search`），每只怪物各有一份黑板、感知、导航与攻击实现，共享 `EnemyAIConfig` 数据配置、`PerceptionManager` 与 `PathRequestScheduler` 两个自动加载服务以及 `EventBus`。普通流式怪物丢失玩家视野超过 `lose_sight_grace` 后，以当前位置作为新巡逻锚点；补给点守卫则固定使用所属补给点，追击与玩家拉开超过 8 格后自行返回，不改写巡逻锚点。感知复用场景中的 `TargetRayCast`（`RayCast2D`）检测物理墙体，并逐格检查程序化地形的可通行性；寻路复用 `AStarGrid2D`，攻击由各怪物自己的 `EnemyAttack` 实现（“仙缔”是 6~10 格投石、6 格内跳跃近战），正式地面可投掷材料（`GroundPickup`，由 `GroundMaterials.THROWABLE_IDS` 指定）已实现投掷接口，仅取1格内可用石头；投石有飞行过程，命中扣1血，落地后仍可拾取，飞行期间不可再次取用。投石与跳跃都不能穿墙。子类通过 `has_player_aggro()` 查询是否处于 Chase / Attack，通过 `clear_player_aggro()` 立刻放弃目标并以当前位置为锚点回到巡逻。“仙缔”只限制生成位置属于沙漠、稀树草原、草原、森林或热带雨林群系，生成后可以追逐玩家进入其他群系。

通用生成器位于 `scripts/monsters/monster_spawner.gd`，生成配置类型位于 `monster_spawn_data.gd`。新增怪物时右键 `scenes/monsters/base_monster.tscn` 创建继承场景，再新建一份 `MonsterSpawnData` 资源并加入 `GameWorld/MonsterSpawner` 的 `spawn_definitions` 数组即可。生成器通过公开的 `monsters: Array[BaseMonster]` 保存存活怪物，怪物死亡时自动移除引用，并在区块卸载或更换世界时遍历释放。`resources/monsters/give_spawn_data.tres` 是“仙缔”的首份配置示例。

统一道具基础层来自 `inventory` 分支：`scripts/items/item_data.gd`、`scripts/items/ingredients/ingredient_data.gd`、`ingredients_model.gd` 以及炼金/物理属性基类保持原路径和原 UID，供背包、合成和世界物品共同使用。

沙晶、冰晶、铁矿、岩盐和雷石等正式地面材料可加入 `throwable_stones` 组供“仙缔”投掷；附近没有可用弹药时，远程攻击停止本次出手。投掷沿用 `IngredientData` / `GroundPickup`，不依赖某一种固定材料 ID。

“仙缔”的动作由场景内 `AnimationPlayer` 和 `AnimationTree` 管理，状态包括 `Idle`、`Move`、`Leap`、`Throw`、`Hurt`、`Death`。在编辑器打开 `scenes/monsters/give_monster.tscn`，选中 `AnimationTree` 可查看状态图，选中 `AnimationPlayer` 可编辑占位动作轨道。动画库为 `resources/monsters/give_animation_library.tres`，状态图为 `resources/monsters/monster_animation_state_machine.tres`；脚本通过通用模板的 `play_monster_animation()` 切换状态。投石和受击完成后自动返回待机，跳跃高度由动画轨道驱动，落点位移与伤害仍由物理逻辑处理。状态图只保留12条转换，以 `Idle` 为中心连接移动与动作；受击和死亡由脚本直接打断。`Death` 没有任何出边，脚本禁止从死亡切回其他状态。死亡状态会立即进入，当前击杀仍直接清理节点，不等待死亡动画播完。

通用模板默认提供受击击退和全身闪红。击退强度按加算叠加：`武器击退强度 + 模板基础击退速度`，方向沿用 `CombatHit.knockback` 的方向，不使用强度乘算。例如武器180、模板40，最终强度为220像素/秒；没有武器击退向量时按攻击来源位置确定方向，仅使用模板基础强度。模板基础速度默认40像素/秒，击退持续0.10秒并逐渐减速，基础位移约2像素；强度180的武器叠加后位移约11像素。`Hurt` 动作在0.10秒内快速左右抖动，初始幅度4像素，再逐渐归零，强化短促冲击感。全身鲜红闪烁持续0.06秒。连续受击会重置反馈时间，材质参数在每只怪物之间独立。击退通过身体碰撞与地形检查阻挡，不会穿过墙体；受击会打断跳跃，进入 `Hurt` 并归零视觉高度。可在根节点“受击反馈”分组调整参数。

外形统一放在 `Visual`（`CanvasGroup`）下面，闪红会作用于全部身体部件、眼睛和轮廓，名字与血条保持原色。“仙缔”的占位绘制位于 `give_monster_visual.gd`。自定义 `_physics_process(delta)` 时先调用 `super._physics_process(delta)`，再在 `is_receiving_knockback()` 为真时跳过自己的移动与攻击，避免覆盖击退位移。

新增怪物的场景流程：

1. 在 Godot 文件系统中右键 `scenes/monsters/base_monster.tscn`，选择“新建继承场景”，保存为新的怪物场景。“仙缔”已经按此方式继承。
2. 修改 `NameLabel.text`、`Health.max_health` 和碰撞形状；在 `Visual` 下隐藏 `Placeholder` 并添加自己的精灵。名字、血条、索敌射线、受击组件、动画节点与信号连接均自动继承。
3. 在 `AnimationPlayer` 的 Libraries 中为新怪物创建或复制独立动画库，保持 `Idle`、`Move`、`Attack`、`Hurt`、`Death` 这些状态对应的动画名；需要特殊技能时可使用 `Leap`、`Throw`。若要修改状态图，先将 `AnimationTree.tree_root` 设为独立资源，避免修改公共状态图影响其他怪物。
4. 为根节点绑定 `extends BaseMonster` 的专属脚本，并指定一份 `EnemyAIConfig`（`resources/monsters/give_ai_config.tres` 是示例）：巡逻半径、视野、攻击距离、搜索时长、LOD 等全部走配置，不需要复制 AI 代码；只有新的攻击方式才需要覆写 `_create_attack()` 返回自己的 `EnemyAttack`。覆盖 `_ready()` 或 `_physics_process(delta)` 时调用对应 `super` 方法。模板已提供生成器初始化、动画推进、寻路动作切换、血条更新与受击/死亡动画连接，无需重复编写。动画库默认使用 `base_animation_library.tres` 的占位动作。
5. 创建 `MonsterSpawnData` 资源，指定新场景和生成群系，再加入生成器的 `spawn_definitions` 数组。

“史莱姆”使用 `scenes/monsters/shi_monster.tscn` 继承怪物模板，并通过独立原始名额在沼泽及山地的可刷怪箱庭生成紧凑群体（10%区块生成概率，每群最多6只）。群体锚点与局部物品/同类索引复用缓存，避免全图数百只史莱姆同步扫描和重绘。单体低跳两次后停1秒；巡逻经过材料时吞入原物品节点，腹内物品按本局原始生成身份保存，卸载和返回不丢失；死亡在尸体位置释放相同数据和数量，可继续 E 拾取。三只组合为“团团史莱姆”，共享总生命、慢速旋转追击，每个成员转到面向玩家一侧发一次0.5伤害粘液弹，实际碰撞接触造成3伤害（持续重叠最多每秒一次）。合团保留三只死亡记录，死亡分别结算80%凝液、20%粘性球的二选一掉落；材料ID6/7，不加入自然材料池。独有机制全部在史莱姆专用脚本，专用 AnimationTree 包含 Idle/Hop/Rest/Form/Spin/Shoot/Hurt/Death，Death 无出边。玩家生命和HUD支持0.5的小数损伤。

鳄鱼“索贝克”使用 `crocodile_monster.tscn` 继承模板，100生命，沼泽原始名额90%水中、10%水边5格内陆地。10格视野，水中巡逻、上岸追击，陆地速度为水中60%；1.5格内咬击造成2伤害，0.18秒前摇、0.4秒动作、1秒冷却。专用 AnimationTree 连接 Idle/Swim/Walk/Attack/Hurt/Death，水中摆尾与四足爬行动作分别驱动，身体和受击胶囊同外观一起转向。死亡单次三选一：鳄鱼眼睛10%、索贝克之壳60%、锋利牙齿30%；返图不补刷。

雪地白兔“糯糯”继承通用怪物模板，80生命，在针叶林、苔原和雪原的可刷怪区域生成，使用模板默认10格仇恨视野。专属脚本驱动两次0.22秒低跳后休息1秒；进入15格攻击距离且无遮挡时原地尖叫4秒，每隔0.8秒释放一层朝向玩家的60度扇形音波，共5层。每层独立从发射点向外传播15格，单层最多命中玩家一次、造成1点伤害，地形/墙体可阻挡；尖叫可被受击打断，随后沿模板寻路逃离玩家，超出15格后在当前位置恢复巡逻。专属 AnimationTree 使用 Idle/Hop/Rest/Scream/Hurt/Death，死亡三选一掉兔皮30%、糯糯肉团50%、胡萝卜20%（材料ID8至10）。
